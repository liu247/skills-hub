# Skills Hub UI 设计规范

本文档定义 Skills Hub 长期稳定的视觉与交互规则，供项目维护者参考。它不是像素级规格表。

最初的 HTML 原型确定了整体设计方向；当前 React 实现可以调整尺寸、间距和组件结构，但应保留本文所述原则。运行时的精确参数以 `src/index.css` 中的设计变量为准。

> 英文版 [`UI-DESIGN-GUIDELINES.md`](./UI-DESIGN-GUIDELINES.md) 是供模型加载的权威版本；本文件仅作为中文参考。

## 本文档应该描述什么

本文档用于判断：

- 视觉层级和信息密度是否符合产品定位；
- 色彩、文字、边框和层级应该承担什么语义；
- 通用控件应该具备哪些行为和状态；
- 导航、浮层、反馈、窗口收缩和无障碍应该如何处理；
- 新界面是否仍然属于 Skills Hub 的设计语言。

本文档有意不包含：

- 固定尺寸、断点或详细间距数值；
- 完整页面清单和组件清单；
- CSS 选择器、React 结构或具体实现步骤；
- 已经属于 i18n 资源的界面文案；
- 某张截图或某个版本中的临时状态。

代码已经能够清楚表达的内容不要重复写入。只有会影响多个后续界面决策的规则，才适合加入本文档。

## 设计定位

Skills Hub 采用中性、现代的工具型风格：安静、紧凑、可靠。它是桌面管理工具，因此清晰度和操作效率优先于装饰效果。

- 当前任务和主要操作必须清楚。
- 优先通过留白、对齐和细边框组织内容。
- 默认保持平面化，仅临时浮层使用明显层级。
- 全局保持单一主要强调色，避免多种装饰色竞争。
- 保持真实的管理工具信息密度，不把管理页面做成大型营销卡片。
- 使用用户熟悉的直接术语，例如 Skills、工具、标签、范围、同步和更新。

## 色彩系统

组件应使用语义化 CSS 变量。已有颜色角色可以满足需求时，不要在组件样式中硬编码颜色。

浅色主题的基准色为：

| 角色 | 基准值 | 用途 |
| --- | --- | --- |
| 应用背景 | `#FAFAFA` | 工作区和导航背景 |
| 面板表面 | `#FFFFFF` | 卡片、表格、表单和弹窗 |
| 主要文字 | `#18181B` | 主要标签和内容 |
| 次要文字 | `#6B6B72` | 说明、元数据和非激活导航 |
| 弱边框 | `#DEDEE1` | 分区和组件边界 |
| 主要强调色 | `#2F6FED` | 主操作、焦点、选中和激活导航 |
| 成功 | `#059669` | 同步正常和操作完成 |
| 警告 | `#D97706` | 需要关注且可恢复的问题 |
| 错误 | `#DC2626` | 失败、危险操作和无效状态 |

这些数值用于说明视觉基线，不表示可以在各组件中重复写死。实际实现使用 `src/index.css` 中的变量，包括深色主题和各种弱化背景。

色彩规则：

- 强调色代表操作、焦点或选中状态，不用于装饰。
- 状态色只表达状态，并且必须同时配合文字或图标。
- 提示和选中行使用弱化的语义背景，避免大面积高饱和色块。
- 浅色和深色主题都必须保证文字对比度。
- 新增颜色必须具有可复用的语义角色，并同时定义浅色和深色变量。

## 字体与图标

- 界面文字使用项目的无衬线 UI 字体栈。
- 路径、版本、命令、代码和技术数值使用等宽字体。
- 优先用字重、颜色和间距建立层级，不要轻易增加新的字号。
- 标签应简洁，说明文字应保持次要层级；产品界面避免装饰性大写文字和营销式标题。
- 使用 Lucide 图标并保持一致的线条风格。图标用于解释操作或对象，不应出现在每个标题旁边。
- 含义不够通用的纯图标操作必须提供可访问名称。

## 布局与层级

- 侧边栏、标题或头部区域、内容工作区以及临时浮层是不同的结构区域。
- 相关控件和数据应对齐到一致的网格，优先保证浏览和扫描效率。
- 高密度管理任务使用表格或结构化列表；发现、选择和分组设置适合使用卡片。
- 每个区域只保留一个主要操作，次要操作和危险操作应降低视觉权重。
- 避免不必要的嵌套卡片；只有真实的交互或归属边界才需要内层容器。
- 需要时让内容区域独立滚动，同时保持持久导航稳定。
- 留白用于分组和聚焦，不用于模拟营销落地页。

## 通用组件行为

### 按钮和控件

- 主按钮用于当前流程最重要的前进操作；次按钮使用中性表面和边框。
- 删除数据或同步目标的危险操作使用错误色，并在影响较大时要求二次确认。
- 禁用控件必须清楚表现为不可用；原因不明显时，应在附近说明缺少的前置条件。
- 输入框默认保持中性，聚焦状态使用明确的强调色；校验信息靠近对应字段。
- 开关用于立即生效的二元设置，多选使用复选框，互斥视图或模式使用分段控件。

### 面板、表格和卡片

- 面板使用内容表面、弱边框和克制的圆角，默认不需要阴影。
- 表格应保持列和行的可扫描性，悬停、选中、禁用、警告和错误状态必须可以区分。
- 发现类卡片应展示名称、来源、简短用途和下一步操作，不重复详情页面内容。
- 标签和徽章只用于紧凑元数据或状态，不用于装饰，也不要重复附近已经明确的信息。

### 导航与侧边栏

- 激活导航通过容器状态、文字对比和图标处理共同表达，不能只依赖状态点。
- 展开状态可以显示名称和确有价值的数量。
- 折叠状态只保留图标和选中状态，隐藏数量角标及状态点；需要时通过可访问的提示显示名称。
- 导航只能切换真实产品区域，不要在产品中加入设计器、视口或主题演示控件。

### 弹窗、抽屉与反馈

- 弹窗用于聚焦决策和确认；抽屉用于需要保留底层页面上下文的内容检查。
- 浮层必须具备清晰标题、关闭方式、键盘行为和操作层级。
- Toast 只确认短暂结果，不能承载用户继续操作所必需的信息。
- 加载状态应说明正在执行什么；耗时操作应在适当时显示进度或允许安全取消。
- 错误信息应说明失败内容和恢复方式，避免模糊的道歉文案。

## 交互与动效

- 每个交互元素都应具备默认、悬停、聚焦、按下、禁用，以及适用的加载或选中状态。
- 动效应短促并解释进入、退出或状态变化，不作为界面装饰。
- 保证键盘操作和清晰的焦点样式。
- 尊重系统的减少动态效果设置。
- 同一流程中的按钮、进度提示、Toast 和结果反馈应使用一致的动作名称。

## 窗口收缩策略

Skills Hub 以桌面端为主，但在较小窗口中仍需可用。

空间不足时按以下顺序调整：

1. 折叠持久导航；
2. 减少多栏布局；
3. 移动次要控件，但不隐藏主要操作；
4. 隐藏或延后低优先级元数据；
5. 当重排会损害理解时，允许高密度数据区域滚动。

不要把完整桌面界面整体等比缩小。文字可读性、操作目标和任务优先级必须保留。

## 无障碍与本地化

- 优先使用语义化控件和有意义的标签，再按需补充 ARIA。
- 不要用颜色作为唯一状态表达方式。
- 弹窗、抽屉、菜单和表单必须保持可见焦点和合理的键盘顺序。
- 布局应容纳较长的中英文文本，不能裁切关键操作。
- 所有产品界面文案都应进入 i18n 资源，并同时提供英文和中文。

## 前端检查清单

提交界面修改前确认：

- 使用已有语义变量，并同时支持浅色和深色主题；
- 层级中存在清楚的主要任务或操作；
- 高密度信息仍然容易扫描；
- 控件具有完整的交互状态和键盘状态；
- 加载、空状态、错误和危险流程都提供下一步；
- 折叠导航隐藏数量角标和状态点；
- 较小窗口和较长本地化文本下仍然可用；
- 没有加入实现专用控制、装饰性色彩或无必要容器。

如果某项功能必须偏离这些规则，应在功能规格或代码评审中说明原因，不要在没有说明的情况下改变全局设计语言。
