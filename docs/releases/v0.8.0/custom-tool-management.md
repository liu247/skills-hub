# 自定义工具管理增强

## 背景

v0.7.0 支持为内部工具或二次封装 Agent 配置自定义 Skills 目录，但自定义工具只能在创建时填写名称和目录，无法表达工具身份，也无法控制目录的同步实现。创建后若目录发生变化，用户只能删除并重新添加配置。

v0.8.0 补齐自定义工具的头像、同步模式和编辑能力，并在修改目录或同步模式时迁移已有同步目标，避免配置与文件系统状态脱节。

## 配置项

| 配置 | 是否必填 | 行为 |
| --- | --- | --- |
| 工具名称 | 是 | 用于工具管理、安装流程和 Skill 卡片中的工具名称。 |
| 工具头像 | 否 | 支持 PNG、JPEG、WebP、GIF 和 SVG，原始文件最大 2 MB；保存前居中裁切并转换为 `128 × 128` PNG。未设置时继续显示文字缩写。 |
| 全局 Skills 目录 | 是 | 托管 Skill 的全局同步根目录，支持 `~` 展开。启用工具时会确保目录存在。 |
| 项目 Skills 目录 | 否 | 相对于项目根目录的同步路径。已有项目级同步目标时不能直接清空该配置。 |
| 同步模式 | 是 | 控制该工具新建和迁移目标时使用的目录同步方式。旧配置默认使用“自动”。 |

## 同步模式

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| 自动 | 依次尝试软链接、Windows 目录联接，失败后回退为复制。 | 默认选择，兼顾性能和平台兼容性。 |
| 软链接 | 只创建软链接，不执行自动回退。 | 已确认工具和操作系统会跟随软链接。 |
| 目录联接 | 只创建 Windows 目录联接，不执行自动回退。 | Windows 工具不适合普通软链接时使用；其他平台会返回不支持错误。 |
| 复制 | 将 Skill 内容复制到目标目录，更新后重新覆盖。 | 工具不会跟随链接，或需要独立实体目录。 |

显式选择软链接、目录联接或复制后，同步失败会直接报告错误，不会静默切换到其他模式。这样可以保证实际目录表示与用户选择一致。

## 创建与编辑

- 新建自定义工具时生成稳定且唯一的工具 key；后续修改名称、头像、目录或同步模式时继续使用原 key，因此已有同步记录无需重新关联。
- 点击卡片底部的编辑按钮后，现有配置会回填到自定义工具表单。保存成功后重新加载工具状态；保存失败时恢复后端中的有效配置和状态。
- 卡片右上角只负责启用或停用；编辑和删除属于管理操作，统一放在卡片底部，避免与即时状态控制混在一起。
- 删除自定义工具会移除工具配置。该操作不等同于删除 Skills Hub 中托管的 Skill。

## 已同步目标迁移

保存编辑结果时，应用会比较修改前后的全局目录、项目目录和同步模式：

1. 名称或头像变化不会移动已有目标。
2. 全局或项目目录变化时，所有仍处于启用状态的该工具目标会同步到新目录，并更新数据库中的目标路径和实际模式。
3. 同步模式变化时，目标会按新模式重新创建；例如从复制切换为软链接后，原实体目录会替换为指向托管 Skill 的链接。
4. 新目标路径已经存在时保存失败，避免覆盖不属于 Skills Hub 的目录。
5. 迁移失败时不会保存新配置；需要重建同一路径表示时，应用会尽力恢复修改前的同步模式。

### 共享目录保护

多个工具可能共享同一个物理 Skills 目录。迁移逻辑不会为了一个自定义工具修改仍被其他同步记录使用的共享目标：

- 新旧路径相同且目标被共享时，保留当前物理表示；新选择的同步模式用于后续新目标。
- 目录变化且旧路径仍被其他记录使用时，只创建并登记新目标，不删除共享旧目标。

该保护避免修改一个工具时破坏另一个工具仍在使用的 Skill。

## 向后兼容

v0.7.x 保存的自定义工具配置没有头像和同步模式字段。v0.8.0 读取旧配置时自动补齐：

- `avatar = null`
- `sync_mode = auto`

因此升级后无需重新创建自定义工具，原目录、启用状态和工具 key 保持不变。

自动化测试覆盖：

- 修改自定义工具目录后的目标迁移；
- 工具 key 保持稳定；
- 复制、软链接和目录联接模式；
- 非 Windows 平台拒绝目录联接；
- 同步模式变化后的目标重建。

完整验证命令：

```bash
npm run check
```
